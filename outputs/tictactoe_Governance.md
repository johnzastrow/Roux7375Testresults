## Developer

Auditing focus: Environment safety, deployment mechanics, local secrets handling, and technical build parameters.

1. **What local runtime environment and package dependencies are required to run, test, and build this application?**
   Go 1.26.5 (go/go.mod, modernc.org/sqlite pure-Go driver, Bubble Tea v2, coder/websocket) and/or a Rust 2024-edition toolchain (cargo workspace of 13 crates; ratatui, axum, rusqlite bundled, argon2). Build via go/Makefile or rust/Makefile; the Rust web clients build with Trunk to WebAssembly. Python plus a browser driver is needed only for the optional e2e and screenshot scripts, which have no declared manifest. Tests: Rust conformance/ws tests and Go _test.go files; no CI workflow in the repo.
2. **How are third-party API credentials and credentials managed?**
   No third-party API credentials exist: no external API hosts are called. The only credential is the pt application password, supplied through PT_PASSWORD / PT_SEED_PASSWORD or generated by the seed command, and stored as an Argon2id hash. Client tokens are cached in a 0600 file under PT_CONFIG_DIR or the OS config directory.
3. **What have you done to make sure the application is secure?**
   Scan positives: no hardcoded secrets or secret files; Argon2id hashing; session cookies HttpOnly and SameSite=Strict (Secure under TLS); loopback-only default bind with a refusal of non-loopback plaintext unless --allow-plaintext; Host/Origin checks and login throttling noted in the Go server code (Rust parity per README); values bound as SQL parameters; Rust workspace forbids unsafe_code.
4. **Are there areas of the application where additional development is planned?**
   Not determinable from the code scan - requires owner input. The repo has CHANGELOG.md and docs/pt/PLAN.md; those were not analysed as a roadmap by the scan.
